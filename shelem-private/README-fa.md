# میز خصوصی شلم پیک، نسخهٔ آزمایشی

این بسته یک سرور واقعی و صفحهٔ وب مستقل برای چهار بازیکن دارد. جایگزین فایل تک‌نفره در GitHub Pages نیست. فایل تک‌نفره و امکانات طرح کارت، زبان‌ها و پیشنهاد به ادمین در نسخهٔ قبلی باقی می‌مانند؛ این صفحهٔ آنلاین فعلاً رابط جدا و فارسی دارد.

## اجرای آزمایشی روی لپ‌تاپ ویندوز

۱. Node.js نسخهٔ ۲۲ یا جدیدتر را از https://nodejs.org نصب کنید.
۲. فایل ZIP را استخراج کنید و در پوشهٔ shelem-private یک Terminal باز کنید.
۳. دستور `npm start` را اجرا کنید. هیچ بستهٔ جانبی نیاز نیست.
۴. روی لپ‌تاپ نشانی http://localhost:3000 را باز کنید.
۵. برای چهار گوشی در یک وای‌فای، نشانی IPv4 لپ‌تاپ را با دستور `ipconfig` پیدا کنید؛ گوشی‌ها نشانی `http://IP-LAPTOP:3000` را باز کنند. بخش IP-LAPTOP را با عدد واقعی جایگزین کنید. لپ‌تاپ باید روشن بماند و فایروال، اتصال ورودی به این برنامه را در شبکهٔ خصوصی مجاز کند. دسترسی ممکن است در وای‌فای با جداسازی کاربران مسدود باشد.

## بازی از شهرها یا اینترنت‌های متفاوت

به یک میزبان Node.js با نشانی عمومی HTTPS نیاز است. همهٔ فایل‌های بسته باید روی همان میزبان قرار بگیرند. فرمان اجرا `npm start` است؛ متغیر PORT در صورت ارائهٔ میزبان خوانده می‌شود. متغیر `PUBLIC_ORIGIN` را روی نشانی دقیق HTTPS سرور، بدون اسلش پایانی تنظیم کنید. نمونهٔ صرفاً شکلی: https://your-server.example

سرور و صفحه باید در یک مبدأ اجرا شوند. فعلاً این صفحه را در GitHub Pages نگذارید؛ API آن روی همان مبدأ است. پس از راه‌اندازی سرور عمومی، می‌توان در صفحهٔ بازی قبلی دکمهٔ «میز خصوصی آنلاین» گذاشت که لینک این صفحه را باز کند.

برای این نسخه فقط یک پردازه/نمونهٔ سرور اجرا کنید؛ افزایش تعداد نمونه‌ها بدون ذخیره‌سازی مشترک، میز را از هم جدا می‌کند. راه‌اندازی عمومی و تأمین میزبان در این بسته انجام نشده است.

## روش بازی

- نفر اول نامش را وارد می‌کند و «ساخت میز خصوصی» را می‌زند. او جایگاه صفر و سازنده است.
- کد یا لینک دعوت را برای سه نفر دیگر می‌فرستد.
- هر نفر نام، کد و جایگاه آزاد را انتخاب می‌کند: یار سازنده، حریف اول یا حریف دوم.
- با هر ورود یا خروج، تأییدهای قبلی پاک می‌شوند؛ هر چهار نفر دوباره ترکیب را تأیید می‌کنند.
- پس از چهار تأیید، سازنده دکمهٔ شروع را می‌زند. تیم‌ها صفر و دو، یک و سه هستند.
- تعهدها به‌ترتیب گرفته می‌شوند. کارت‌ها، نوبت، برنده و امتیاز فقط در سرور تعیین می‌شوند.
- هر بازیکن فقط دست خودش را دریافت می‌کند. توکن بازگشت در مرورگر خودش ذخیره می‌شود؛ کد دعوت شامل توکن نیست.
- بعد از قطع اینترنت، همان مرورگر را دوباره باز کنید. نوبت خودکار سپری نمی‌شود و بازی منتظر بازگشت می‌ماند. حضور با آخرین ارتباط تخمین زده می‌شود.
- ادامهٔ دور یا مسابقهٔ جدید با سازنده است.

## قانون جوکر سیاه

دارندهٔ جوکر سیاه اگر با سه برگ، شروع‌کنندهٔ دست یازدهم باشد، فوراً باعث باخت تیم می‌شود و اجازهٔ بازی ندارد. اگر نفر دیگر شروع کرده باشد، همان نوبت آخرین فرصت اوست. انتخاب کارت دیگر باعث پایان دور و منفی ده برابر تعهد تیم می‌شود. گزارش مشترک نام بازیکن متخلف و علت را نشان می‌دهد.

## حدود نسخه

- حساب کاربری، رتبهٔ سراسری و ذخیرهٔ دائمی امتیاز هنوز ندارد؛ نام نمایشی، احراز هویت نیست.
- با اتصال Supabase، کارت‌ها، توکن بازگشت، نوبت و امتیاز تیم در پایگاه داده ذخیره و بعد از راه‌اندازی دوباره بازیابی می‌شوند. بدون تنظیم ذخیره‌ساز، اجرای محلی فقط حافظه‌ای است. میز بدون فعالیت پس از ۲۴ ساعت حذف می‌شود.
- بیرون‌انداختن بازیکن، انتقال مالکیت، تماشاگر و جایگزینی فرد در بازی جاری اضافه نشده‌اند.
- کسی که کد دعوت دارد، تا پیش از شروع می‌تواند جایگاه آزاد را بگیرد. کد را فقط برای افراد موردنظر بفرستید.
- تست چهار نشست HTTP مستقل، تأیید ترکیب، جلوگیری از حرکت خارج نوبت و تکرار حرکت، محرمانگی دست و بازگشت با توکن انجام شده است. اجرای بصری در آیفون/اندروید آزمایش نشده است.

## بررسی فنی

`npm test` آزمون چهار نشست HTTP و قطع ناگهانی پردازه و بازیابی بازی را اجرا می‌کند.
سرور از موتور قواعد نسخهٔ اصلاح‌شده در engine-source.html استفاده می‌کند؛ این فایل در مسیر عمومی سرو نمی‌شود. ربات، ذخیرهٔ رتبهٔ محلی و تایمر تک‌نفره برای میز آنلاین غیرفعال‌اند. به‌روزرسانی صفحه با دریافت وضعیت هر یک ثانیه انجام می‌شود؛ این نسخه از WebSocket استفاده نمی‌کند.

## حاکم، پخش برگ‌ها و تعهد

دور اول با قرعهٔ سرور آغاز می‌شود. حاکم در دورهای بعد تا وقتی امتیاز کل تیمش بالاتر است باقی می‌ماند. جلو افتادن حریف، حاکمی را به بازیکن بعدی ساعت‌گرد منتقل می‌کند. اگر امتیاز برابر باشد، هشت‌های خنثی‌نشده ملاک‌اند؛ تساوی کامل باعث حفظ حاکم است. در مسابقهٔ جدید قرعه دوباره انجام می‌شود.

در هر مرحله، بستهٔ حاکم اول داده می‌شود و سپس بقیه ساعت‌گرد: یک بستهٔ پنج‌برگی برای هر چهار نفر، سپس یک بستهٔ چهاربرگی برای هر چهار نفر و در پایان یک بستهٔ چهاربرگی دیگر برای هر چهار نفر. پخش در سرور انجام می‌شود؛ نمایش کارت‌ها پس از تکمیل پخش است و انیمیشن بسته‌ها فعلاً ندارد.

اعلام تعهد و اولین دست از حاکم شروع می‌شوند. جهت گردش تعهد و بازی ساعت‌گرد است. روی میز: پایین، چپ، بالا، راست؛ هم‌تیمی‌ها روبه‌روی هم‌اند.

## راه‌اندازی آزمایشی رایگان با Render و Supabase

۱. در Supabase یک پروژه با پلن Free بسازید. در SQL Editor فایل supabase-schema.sql را اجرا کنید. جدول کارت‌ها و توکن‌ها برای کاربران عمومی قابل خواندن نیست.
۲. از تنظیمات پروژه، Project URL و Secret API key را دریافت کنید. کلید محرمانه فقط در تنظیمات سرور قرار می‌گیرد؛ آن را در HTML، GitHub، پیام یا تصویر منتشر نکنید. کلید publishable یا anon مناسب این اتصال نیست.
۳. پوشهٔ این بسته را در یک مخزن GitHub قرار دهید. در Render یک Web Service از همان مخزن بسازید؛ اگر پوشه داخل مخزن است، Root Directory را shelem-private بگذارید. Runtime: Node، Build Command: node --version، Start Command: npm start، Instance: Free. فایل render.yaml نیز همین تنظیمات را برای Blueprint ارائه می‌کند؛ با همان ساختار پوشهٔ ZIP.
۴. در Environment سرور این متغیرها را تنظیم کنید:

| نام | مقدار |
|---|---|
| NODE_VERSION | 22 |
| REQUIRE_PERSISTENCE | true |
| SUPABASE_URL | Project URL پروژهٔ خودتان |
| SUPABASE_SECRET_KEY | Secret key سرور، یا service_role قدیمی |
| PUBLIC_ORIGIN | نشانی HTTPS سرویس Render بدون اسلش پایانی |

۵. پس از انتشار، نشانی سرویس را در چهار مرورگر باز کنید، میز بسازید و یک دور بازی کنید. برای آزمون بازیابی، سرویس را از پنل Restart کنید و با همان مرورگرها برگردید. این آزمون ابری هنوز انجام نشده؛ آزمون بازیابی فعلی روی پردازهٔ واقعی محلی بوده است.

قاعدهٔ ۱۵ دقیقهٔ Render مربوط به نبود درخواست است، نه طول مسابقه. صفحهٔ باز بازی درخواست وضعیت می‌فرستد. بعد از خواب سرویس، بازشدن ممکن است حدود یک دقیقه طول بکشد. بازیابی فقط با ذخیره‌ساز درست و در دسترس ممکن است؛ هنگام خطای ذخیره، حرکت تأیید نمی‌شود و باید دوباره تلاش کرد. میز بی‌فعالیت پس از ۲۴ ساعت حذف می‌شود.

پلن‌های رایگان سهمیه دارند؛ سقف کاربران قابل پشتیبانی هنوز اندازه‌گیری نشده است. Supabase Free بعد از یک هفته بی‌فعالیتی ممکن است متوقف شود و پشتیبان خودکار ندارد. Render نیز امکان راه‌اندازی مجدد یا تعلیق بر اثر سهمیه دارد. برای آزمایش اولیه سراغ ارتقای پولی یا افزودن کارت پرداخت نروید. دسترسی از ایران و خارج ایران باید با گوشی‌های واقعی آزمایش شود؛ در قطع اینترنت بین‌المللی، این ترکیب خارجی در دسترس نخواهد بود.

این نسخه تمام میزها را در یک رکورد ذخیره می‌کند و فقط یک نمونهٔ سرور مجاز است؛ برای آزمایش جمع کوچک است. حساب کاربری و جدول رتبهٔ سراسری هنوز پیاده‌سازی نشده‌اند.

منابع محدودیت‌ها: https://render.com/docs/free و https://supabase.com/pricing

برای حفظ بازی روی لپ‌تاپ، پیش از npm start در PowerShell دستور `$env:STATE_FILE="./data/state.json"` را اجرا کنید. از STATE_FILE روی Render رایگان استفاده نکنید؛ فایل‌های آن با راه‌اندازی دوباره از دست می‌روند.
